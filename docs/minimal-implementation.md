# 最小構成の実装

## 起動と確認

```sh
npm run dev
npm test
npm run test:watch
npm run build
```

テストはVitestを使用する。`npm test`で一度実行し、`npm run test:watch`で変更を監視しながら実行できる。ブラウザー確認はユーザーからの明示的な依頼がある場合のみ行う。

## 操作の流れ

1. 2D換算解像度、基準平面の高さ、垂直FOVを設定して「適用」を押す。初期値は1920×1080、高さ5、45°。
2. 一覧からレイヤー1・レイヤー2・地面を選び、それぞれ画像を読み込む。PNG・JPEG・WebPを使用し、画像は共通キャンバス全体へ対応付ける。画像の実解像度は異なっていてもよい。縦横比が異なる場合も読み込みを許可し、画像欄の近くに伸縮表示の通知を出す。設定変更時やレイヤー選択時にも現在の画像と2D換算解像度から再判定し、比率が合えば通知を消す。切り詰め画像の配置矩形指定は次の段階。
3. 正面レイヤーのZを変更して視差を付ける。基本は2D位置・サイズを維持する。通常の3D移動・サイズ変更は別の入力欄から行う。
4. 「基準面との関係」で平行／垂直を選び、垂直なら下（地面）・上（天井）・左（壁）・右（壁）を選ぶ。配置基準点のX・Y、面の幅または高さを調整し、地面・左右壁・天井は手前端Z・奥端Zで奥行き範囲を指定する。配置基準点のZは0固定。地面の高さは基準点Yで指定する。
5. 左右・上下スライダーで視差を確認する。「基準へ戻す」で確認用カメラのみをリセットする。
6. 配置確認ビューをドラッグし、別角度からPlaneを確認する。実表示・投影範囲確認・識別色表示を切り替えられる。
7. 必要に応じて「周囲を表示」を使い、プレビューの基準枠外を確認する。

初期サンプルは`public/samples/background.png`（遠景）、`foreground.png`（前景）、`ground.png`（地面）のPNGファイルを起動時に読み込む。すべて1920×1080。画像ファイルを直接確認・編集でき、同名のファイルを差し替えてページを再読み込みすると反映される。地面も独立した画像を読み込める。画像はブラウザー内で処理し、外部にアップロードしない。読み込み上限は32MB、各辺8192pxまたはGPUの上限の小さい方。

座標の基準・操作方法・表示ガイドは画面上部の「ヘルプ」、算出された基準面サイズとカメラZは「カメラ情報」で確認できる。常時表示の補足を減らし、数値入力と選択肢を中心に構成する。

## 検証用の挙動

- 基準平面はz=0。高さを保存するモデルとし、幅・px換算値・正のカメラZを導出する。
- 初期状態は正面向きレイヤー2枚と水平地面1枚。各レイヤーは基準面との関係と面の向きを分けて指定する。表示方式は平行なら頂点UV、垂直ならTSL投影に自動で切り替わる。追加・削除と自由な回転角の入力は扱わない。
- 向きと位置は別の設定。「下（地面）」もY位置を固定せず、配置基準点Yで上下に動かせる。
- 配置基準点とPlaneの中心を分離する。基準点はz=0上に置き、初期値は正面が中央、地面が下辺中央、左右壁が左右辺中央、天井が上辺中央。基準点のX・Yを変更すると、面も同じ量だけ移動する。Planeの奥行き範囲は基準点と別に両端座標として保持する。初期地面は手前端Z=0、奥端Z=-28とし、原点から奥へ延ばす。中心Z=-14と奥行き28は両端から算出する値であり、直接編集しない。手前への延長は必要な場合に明示的に指定する。
- 関係・向きの変更時は、基準点を選択した面の初期位置へ変更し、面の向きを切り替える。画像とサイズは維持し、地面・天井の高さと壁の左右位置は新しい基準点に合わせる。配置確認ビューの各面の小さなXYZ軸は、その配置基準点とローカル軸を示す。
- 初期の遠景Plane（レイヤー1）はz=-40とし、地面の奥端z=-28より奥へ配置する。基準カメラからの2D位置・サイズを保つようPlaneを拡縮する。これは初期配置であり、地面サイズ変更時に遠景を自動追従させるものではない。
- 地面サンプルは黄緑の帯を含めず、黄色地に96px間隔の薄い正方形グリッドを入れる。画像自体にパースは付けず、投影後の変形を確認する目印として使う。画像の上端は初期地面の奥端を基準カメラへ投影した位置（約636px）に合わせ、その上は透明にする。地面の初期幅は60とし、その上端で画面の横幅を覆えるようにする。PNGはこの初期配置に合わせて用意した固定の画像とし、実行時にCanvasで生成しない。変更後のFOVや地面配置に合わせて元画像を描き換えることはしない。
- FOVや基準設定の適用時は、正面レイヤーの「2D配置を保つ／3D配置を保つ」を比較できる。2D維持の場合もレイヤーZは保持する。これは最終仕様を判断するための検証用切り替え。
- 地面・左右壁・天井はFOV変更時に、カメラZの変化率と同じ倍率で手前端Z・奥端Zを伸縮する。中心Zと奥行きサイズは、その両端から導出する。地面・天井の奥行きはPlaneのローカルY方向（height）、左右壁の奥行きはローカルX方向（width）に対応する。基準平面の高さが一定なら、基準カメラからの各面の見え方を維持できる。地面・天井は高さと横幅、左右壁は左右位置と高さを維持し、正面レイヤーの維持モードとは独立して適用する。倍率はFOVの変化分のみから求め、基準高さや解像度だけの変更では面を伸縮しない。両端座標は手前端Z > 奥端Zを満たす有限の値とし、逆転や長さ0の入力は適用しない。
- 地面・左右壁・天井のFOV補正でも配置基準点のX・Yは維持し、Zは0のままとする。
- 基準カメラの変更で投影を更新する。視差確認・配置確認用カメラの操作は編集モデルを変更しない。
- 描画はWebGPURendererを使用し、両ビューの非同期初期化後に操作・描画を開始する。WebGPUを優先し、利用できない場合はThree.js標準のWebGL 2バックエンドへフォールバックする。[Three.js公式ドキュメント](https://threejs.org/docs/pages/WebGPURenderer.html)
- 平行な面は配置・基準設定の変更時に各頂点の投影UVを求め、以降はそのUVで画像を参照する。垂直な面はMeshBasicNodeMaterialとTSLで、フラグメントごとに基準カメラの透視投影を計算する。UV範囲外は端の色・アルファを延長する。カメラ背面・near/far外は実表示では描画せず、範囲確認では赤く示す。WebGL用のonBeforeCompileやGLSL文字列置換は使用しない。
- 投影元の基準カメラはNDCのZ範囲を-1〜1へ固定する。描画用カメラのバックエンド座標系とは分離し、WebGPUでも範囲判定の意味を変えない。
- 配置確認は裏面からも見える補助表示とし、通常プレビューは片面表示。輪郭は透過余白も含むPlane全体を示す。
- カメラの視野ガイドは見やすい長さに短縮しており、実際のfar面の位置を示すものではない。
- 元画像比較はレイヤー1→地面→レイヤー2の固定順で2D合成する。3D変形や有限な地面の形状を再現する比較画像ではない。OPAQUE指定でも、比較元は入力画像の透過情報をそのまま使う。
- 識別色は各レイヤーの`editorColor`としてメモリー上の編集モデルで保持する。

## 今回の対象外

JSON保存・復元、頂点UVによるGLB出力、カメラ追従の背景Plane、PSD読み込み、切り詰め画像の配置、ギズモ、自動カメラ移動。GLBは元画像と各頂点の投影UVを保存する方針であり、新たな画像を生成するベイクは基本方式にしない。現段階ではリロードすると編集内容は失われる。

## 実施した確認

座標変換・奥行き変更・FOV変更・解像度変更・不正値の拒否に加え、配置基準点、各方向の面の向き、既存地面の四隅の維持を自動テストで確認する。今回の変更は型チェックとViteビルドを実施し、ブラウザー確認は未実施。以前の投影・サンプル表示は、ユーザーからの依頼に応じてブラウザーで確認している。
