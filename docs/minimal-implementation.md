# 最小構成の実装

## 起動と確認

```sh
npm run dev
npm test
npm run test:watch
npm run build
```

テストはVitestを使用する。`npm test`で一度実行し、`npm run test:watch`で変更を監視しながら実行できる。ブラウザー確認はユーザーからの明示的な依頼がある場合のみ行う。

## 操作の流れ

1. 2D換算解像度、基準平面の高さ、垂直FOVを設定して「適用」を押す。初期値は1920×1080、高さ5、45°。
2. 一覧からレイヤー1・レイヤー2・地面を選び、それぞれ画像を読み込む。PNG・JPEG・WebPを使用し、画像の縦横比を保った中央基準のcoverで共通キャンバスを覆う。画像の実解像度は異なっていてもよい。縦横比が異なる場合も読み込みを許可し、画像欄の近くに中央クロップ表示の通知を出す。設定変更時やレイヤー選択時にも現在の画像と2D換算解像度から再判定し、比率が合えば通知を消す。切り詰め画像の配置矩形指定は次の段階。
3. 正面レイヤーのZを変更して視差を付ける。基本は2D位置・サイズを維持する。通常の3D移動・サイズ変更は別の入力欄から行う。
   正面レイヤーの「配置 · px」では、共通キャンバスの左上を原点とするX・Y・幅・高さを入力できる。Xは右、Yは下が正。正本の矩形を直接更新し、Zと配置基準点は維持する。枠外の位置や小数を許可し、幅・高さは正の値とする。3D配置の入力後は、その変更を反映した2D矩形を表示する。
4. 「基準面との関係」で平行／垂直を選び、垂直なら下（地面）・上（天井）・左（壁）・右（壁）を選ぶ。配置基準点のX・Y、面の幅または高さを調整し、地面・左右壁・天井は手前端Z・奥端Zで奥行き範囲を指定する。配置基準点のZは0固定。地面の高さは基準点Yで指定する。
   平行・垂直ともに「配置 · px」「配置基準点 · px」を基本入力とし、その下の「3D配置」を開くとシーン単位で同じ配置を編集できる。地面・壁・天井では中心・寸法・両端Z・配置基準点を扱い、辺の補足も入力単位に合わせる。平行のZと配置基準点も基本側はpx相当で入力する。初期地面のYは基本側で-540、3D配置では-2.5となる。開閉だけでは配置は変わらず、編集後も開閉状態を維持する。
5. 左右・上下スライダーで視差を確認する。「基準へ戻す」で確認用カメラのみをリセットする。
6. 配置確認ビューをドラッグし、別角度からPlaneを確認する。実表示・投影範囲確認・識別色表示を切り替えられる。
7. 必要に応じて「周囲を表示」を使い、プレビューの基準枠外を確認する。
8. レイヤー一覧の「追加」で画像を選ぶと、新しいレイヤーを追加して選択する。初期状態は基準面に平行な正面向き、Z=0、共通キャンバス全体のサイズ、BLEND。名前は画像のファイル名から付ける。その後、向きや位置を編集できる。
9. 選択中のレイヤーの「削除」で、そのレイヤーを削除する。次のレイヤー、末尾なら前のレイヤーを選択する。全レイヤーを削除してから再追加することもできる。最大9枚とし、上限では追加ボタンを無効にする。
10. 選択中のレイヤーの「上へ／下へ」で一覧順を入れ替える。先頭の「上へ」と末尾の「下へ」は無効。選択、画像、3D位置は維持する。同じZの元画像比較は一覧の後ろほど上に重なる。

11. 画面上部の「JSON保存」で`three-layered-scene.json`をダウンロードする。適用済みの基準設定、一覧順のレイヤー、px相当値の配置、元画像を1ファイルに保存する。元画像はPNG・JPEG・WebPの元データを再圧縮せず埋め込み、`assets`はJSONの最後に置く。確認用カメラや一時的な表示状態は保存しない。保存処理の開始後に編集しても、クリック時点の内容を保存する。

12. 「JSON読み込み」で保存済みJSONを選ぶと、全データと画像の検証後に編集内容を置き換える。失敗した場合は編集中の内容を残してエラーを表示する。先頭レイヤーを選択し、空のシーンも読み込める。確認用カメラや表示設定は現在の状態を維持する。画像のアスペクト比が異なる場合は既存の通知を表示する。

13. 「GLB書き出し」で`three-layered-scene.glb`をダウンロードする。表示中のPlane・頂点UV・unlitマテリアル・元画像・基準カメラを出力する。元画像の再圧縮・WebP／KTX2変換は行わない。地面・壁・天井は8×8のGrid（81頂点・128三角形）でプレビュー用に近似する。最終表示での投影はシェーダーで再計算する方針とする。投影カメラの背面・near/far外に頂点がある面は、配置を調整してから再度書き出す。

初期サンプルは`public/samples/background.png`（遠景）、`foreground.png`（前景）、`ground.png`（地面）のPNGファイルを起動時に読み込む。すべて1920×1080。画像ファイルを直接確認・編集でき、同名のファイルを差し替えてページを再読み込みすると反映される。地面も独立した画像を読み込める。画像はブラウザー内で処理し、外部にアップロードしない。読み込み上限は32MB、各辺8192pxまたはGPUの上限の小さい方。

座標の基準・操作方法・表示ガイドは画面上部の「ヘルプ」、算出された基準面サイズとカメラZは「カメラ情報」で確認できる。常時表示の補足を減らし、数値入力と選択肢を中心に構成する。

## 検証用の挙動

- 配置の正本はpx相当値で保持し、描画・入力欄向けのシーン値をgetterで算出する。通常の入力はpxを基本とし、シーン単位の入力は平行・垂直ともに折りたたみの「3D配置」にまとめる。正面は2D矩形とZ、地面・壁・天井は配置基準点と横幅または高さ・両端Zを正本とする。3D入力はsetterや既存操作を通して対応する正本を更新し、未変更の値を不要に逆変換しない。詳細は仕様書の「編集モデルの正本と3D入力」を参照。
- 基準平面はz=0。高さを保存するモデルとし、幅・px換算値・正のカメラZを導出する。
- 初期状態は正面向きレイヤー2枚と水平地面1枚。各レイヤーは基準面との関係と面の向きを分けて指定する。表示方式は平行なら頂点UV、垂直ならTSL投影に自動で切り替わる。自由な回転角の入力は扱わない。
- 画像の選択をキャンセルした場合や画像の読み込みに失敗した場合は追加しない。レイヤーと画像・描画リソースは安定したIDで対応付け、削除時にリソースを解放する。編集中の削除で元の画像ファイルは削除しない。
- 向きと位置は別の設定。「下（地面）」もY位置を固定せず、配置基準点Yで上下に動かせる。
- 配置基準点の入力欄の近くに、地面は基準面の下端Y、天井は上端Y、左右壁は左端・右端Xを表示する。基準面の高さ・解像度の設定変更時にも更新し、配置基準点そのものは変更しない。正面向きには辺の座標を表示しない。
- 辺の座標はX・Y欄の組の下に両列にまたがる補足として表示する。Zの基準「基準面 Z = 0」は奥行きZまたは手前端Z・奥端Zの欄の近くに同じ形式・文字サイズ・色で表示し、「配置基準点」の見出しからは外す。
- 配置基準点とPlaneの中心を分離する。基準点はz=0上に置き、初期値は正面が中央、地面が下辺中央、左右壁が左右辺中央、天井が上辺中央。基準点のX・Yを変更すると、面も同じ量だけ移動する。Planeの奥行き範囲は基準点と別に両端座標として保持する。初期地面は手前端Z=0、奥端Z=-28とし、原点から奥へ延ばす。中心Z=-14と奥行き28は両端から算出する値であり、直接編集しない。手前への延長は必要な場合に明示的に指定する。
- 関係・向きの変更時は、基準点を選択した面の初期位置へ変更し、面の向きを切り替える。画像とサイズは維持し、地面・天井の高さと壁の左右位置は新しい基準点に合わせる。配置確認ビューの各面の小さなXYZ軸は、その配置基準点とローカル軸を示す。
- 初期の遠景Plane（レイヤー1）はz=-40とし、地面の奥端z=-28より奥へ配置する。基準カメラからの2D位置・サイズを保つようPlaneを拡縮する。これは初期配置であり、地面サイズ変更時に遠景を自動追従させるものではない。
- 地面サンプルは黄緑の帯を含めず、黄色地に96px間隔の薄い正方形グリッドを入れる。画像自体にパースは付けず、投影後の変形を確認する目印として使う。画像の上端は初期地面の奥端を基準カメラへ投影した位置（約636px）に合わせ、その上は透明にする。地面の初期幅は60とし、その上端で画面の横幅を覆えるようにする。PNGはこの初期配置に合わせて用意した固定の画像とし、実行時にCanvasで生成しない。変更後のFOVや地面配置に合わせて元画像を描き換えることはしない。
- FOVや基準設定の適用時は、正面レイヤーの「2D配置を保つ／3D配置を保つ」を比較できる。2D維持の場合もレイヤーZは保持する。これは最終仕様を判断するための検証用切り替え。
- 地面・左右壁・天井はFOV変更時に、カメラZの変化率と同じ倍率で手前端Z・奥端Zを伸縮する。中心Zと奥行きサイズは、その両端から導出する。地面・天井の奥行きはPlaneのローカルY方向（height）、左右壁の奥行きはローカルX方向（width）に対応する。基準平面の高さが一定なら、基準カメラからの各面の見え方を維持できる。地面・天井は高さと横幅、左右壁は左右位置と高さを維持し、正面レイヤーの維持モードとは独立して適用する。倍率はFOVの変化分のみから求め、基準高さや解像度だけの変更では面を伸縮しない。両端座標は手前端Z > 奥端Zを満たす有限の値とし、逆転や長さ0の入力は適用しない。
- 地面・左右壁・天井のFOV補正でも配置基準点のX・Yは維持し、Zは0のままとする。
- 基準カメラの変更で投影を更新する。視差確認・配置確認用カメラの操作は編集モデルを変更しない。
- 描画はWebGPURendererを使用し、両ビューの非同期初期化後に操作・描画を開始する。WebGPUを優先し、利用できない場合はThree.js標準のWebGL 2バックエンドへフォールバックする。[Three.js公式ドキュメント](https://threejs.org/docs/pages/WebGPURenderer.html)
- 平行な面は配置・基準設定の変更時に各頂点の投影UVを求め、以降はそのUVで画像を参照する。垂直な面はMeshBasicNodeMaterialとTSLで、フラグメントごとに基準カメラの透視投影を計算する。UV範囲外は端の色・アルファを延長する。カメラ背面・near/far外は実表示では描画せず、範囲確認では赤く示す。WebGL用のonBeforeCompileやGLSL文字列置換は使用しない。
- 投影元の基準カメラはNDCのZ範囲を-1〜1へ固定する。描画用カメラのバックエンド座標系とは分離し、WebGPUでも範囲判定の意味を変えない。
- 配置確認は裏面からも見える補助表示とし、通常プレビューは片面表示。輪郭は透過余白も含むPlane全体を示す。
- カメラの視野ガイドは見やすい長さに短縮しており、実際のfar面の位置を示すものではない。
- 画像配置は中央基準のcover。透過領域を含む画像キャンバス全体を使い、画像と基準枠の寸法から中央のクロップ範囲とUV変換を共通関数で求める。元画像比較はその範囲を描画し、平行・垂直のどちらの3D表示も同じUV変換を使う。画像差し替え・2D換算解像度の変更時に再計算する。
- 範囲確認の判定はcover適用前の基準枠UVを使う。枠外でも元画像の残りの部分を参照し、画像範囲を越えてから端の色・アルファを延長する。
- 元画像比較は各レイヤーの中心Zが小さい順（奥から手前）に2D合成する。地面・壁・天井は手前端Z・奥端Zから算出される中心Zを使う。同じZなら一覧順に重ねる。追加・削除・Z位置や設定の変更時に再計算し、一覧順自体は変更しない。3D変形、面同士の交差や有限な地面の形状を再現する比較画像ではない。OPAQUE指定でも、比較元は入力画像の透過情報をそのまま使う。
- 一覧順の変更時も元画像比較を更新する。3D側はThree.jsの不透明・透過別の描画と深度ソートを維持し、同じ描画深度の面は一覧順で描画する。同じZの平行な面は基準カメラでこの順序になる。別角度で深度が異なる場合や、OPAQUEとBLENDの混在・面の交差は単純な画像の重ね順とは一致しない。
- 識別色は各レイヤーの`editorColor`としてメモリー上の編集モデルで保持する。
- 平行・垂直とも画像は`material.map`に設定し、TSLはそのmapを参照して通常UVまたは投影UVでサンプリングする。画像差し替えとcover計算の画像参照もmapへ統一する。

## 今回の対象外

WebP・KTX2変換、GLB表示のブラウザー検証と分割数の最適化、カメラ追従の背景Plane、PSD読み込み、切り詰め画像の配置、ギズモ、自動カメラ移動。GLBは元画像と各頂点の投影UVを保存する方針であり、新たな画像を生成するベイクは基本方式にしない。自動保存はなく、リロードすると初期状態へ戻る。保存済みのJSONを読み込むことで編集を再開できる。

## 実施した確認

座標変換・奥行き変更・FOV変更・解像度変更・不正値の拒否に加え、配置基準点、各方向の面の向き、既存地面の四隅の維持を自動テストで確認する。追加・削除については、新規配置、枚数上限、削除後の選択、全削除後の再追加、合成順、IDによる描画リソースの再利用・解放を確認する。今回の変更は型チェックとViteビルドを実施し、ブラウザー確認は未実施。以前の投影・サンプル表示は、ユーザーからの依頼に応じてブラウザーで確認している。

px相当値への整理では、デモの正本の値、3D入力からの更新、2D維持のZ・FOV変更で矩形をそのまま保持すること、各向きの両端・基準点の更新、基準高さ・解像度変更時の配置、不正入力で正本が変わらないことを確認する。

JSON保存では、出力の項目・配列順、各向きのpx相当値と小数精度、画像参照、元画像バイトの一致、非同期処理中の変更との分離、全削除時や画像取得失敗時の挙動を自動テストで確認する。ブラウザーでのダウンロード操作は未確認。

JSON読み込みでは、保存→読み込み→再保存による数値・画像バイト・一覧順の維持、各面の復元、空シーン、共有画像参照、不正データ・画像デコード失敗の拒否、描画リソース切り替えの失敗時の復元を自動テストで確認する。読み込み中は旧シーンを保持し、成功後に旧テクスチャを解放する。読み込みのブラウザー確認は未実施。

GLB書き出しは、元画像バイトの一致、標準のunlitと透過設定、GLBのチャンクと画像参照、クランプ設定、共有画像、非表示レイヤーの除外、カメラのみの出力を確認する。Three.jsのGLTFLoaderで形状・UV・カメラを読み戻し、各面の全頂点のUVを基準カメラの投影と照合する。テストでは画像デコードだけを置き換えており、ブラウザーや一般ビューアーでの表示確認は未実施。

GLBのシーン・投影カメラ・各Planeのメッシュに`extras.threeLayeredScene`を格納する。GLTFLoaderのuserDataからレイヤーID・投影カメラ参照・UV変換を取得し、編集JSONなしで専用表示を復元できる形式とする。形式と利用手順は[GLBからの投影表示の復元](./glb-projection.md)を参照。独立した利用側のTSL実装は`src/viewer.ts`と`viewer.html`に用意する。


## 独立したGLBビューアー

開発サーバーの`/viewer.html`から利用する。エディターで書き出したGLBを選び、「TSL投影／標準表示」と「基準カメラ／配置確認」を切り替えられる。編集JSONやエディター側モジュールは読み込まない。ビルド時は`dist/viewer.html`も出力する。操作と制限は[GLBからの投影表示の復元](./glb-projection.md)を参照。ブラウザー確認は未実施。
